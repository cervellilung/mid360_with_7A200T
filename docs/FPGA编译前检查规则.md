# FPGA 编译前检查规则



用户长期要求：每次 FPGA 修改后，先进行面向目标器件的结构审查和必要优化，再启动编译。不能等布线拥塞才检查写法。适用于仿真、局部综合和整机构建；检查深度与本轮改动范围匹配，不因未改动的厂商 IP 重复大规模审查。



## 固定顺序



1. 阅读活动顶层、接口、时钟/复位、约束、相关 RTL 和最新工具报告，识别实际数据流。

2. 对本轮修改明确综合后的结构：存储深度/位宽/端口/同步性、MUX、运算位宽、流水线、控制集、扇出和跨模块连线。

3. 编译前处理明显不合理的结构；优先单写口 RAM、可靠 BRAM/LUTRAM 模板、必要的数据有效标记、合理位宽和明确 CDC。不能用错误 false path、multicycle 或随意降频掩盖问题。

4. 在本轮记录中说明预期 LUT/FF/Slice/BRAM/DSP 影响、延迟与吞吐变化、复位及缓冲区所有权。未确认的结构风险必须写明。

5. 先 syntax/elaboration 和有意义的仿真，再局部综合核对真实推断和资源；整机综合通过后检查层次资源、control sets、high fanout、关键路径及 CDC/RDC。

6. 资源、打包、时序和约束有依据后才进入布局；布局出现高 Slice、局部拥塞或不合理时序时先分析根因，不能直接反复 route。最终路由 WNS/WHS≥0、DRC/引脚及相关 CDC 审核通过后才发布候选 bit。



## 判断原则



- Slice 没有通用的安全百分比。70% 以上列为本项目的审查触发线，而非器件不能实现的硬性上限；低于此值也可能局部拥塞。

- LUT/FF 占用低但 Slice 高时，优先检查控制集、寄存器打包和局部存储/选择网络，不能只盯 LUT。

- 软件循环简洁不代表硬件合理。变量索引、多地址写数组、宽总线、动态移位和除法必须分析综合结构。

- 预审只能排除已知结构风险，不能替代综合、布局布线和硬件验证。报告明确区分预期与实测。

- 使用统一 tools/run_build.py 打开图形监视器；两套重构建依次进行，默认20线程，服从工具自身并行上限。

- 只修改 vivado_project 下现行工程，保留旧项目和厂商原工程；文档放 docs，根目录 README 仅作索引。
- 每次任务完成后先更新 docs/项目总交接.md，再报告完成；记录修改、验证证据、未解决问题与具体下一步。暂停或受阻也更新状态，详细报告在 docs 中链接归档。

## XDC 执行与 CDC 约束验收补充（2026-10-06）

- Vivado XDC 中使用工具支持的约束命令；条件判断、异常退出、端点数量检查放在普通 Tcl 构建脚本。不要假定任意 Tcl 语法都能在 XDC 正常执行。
- 审计不能只验证 get_cells 有结果：必须检查约束解析警告、实际 get_timing_paths 的 REQUIREMENT、report_exceptions -coverage 和 report_bus_skew；端点丢失或 requirement 与设计预算不符，构建脚本应退出失败。
- 针对握手 bundled bus，报告源稳定窗口、同步级、数据捕获关系、物理max_delay和skew。不得用全域false_path替代物理约束；数字仿真不证明CDC物理安全。
