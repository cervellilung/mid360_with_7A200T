### 根因（锁定在我们设计的 RX 时钟架构）



```

厂商（能通）：RXC ──────────────→ BUFG ──→ IDDR

我们（全死）：RXC → eth_phase_mmcm(M=8,D=1,VCO=1000) → 原始CLKOUT

                    → u_udp_pts 内部 BUFG(clk125m) → IDDR + 全部网口逻辑

```



首要怀疑（按序）：



1. **`eth_phase_mmcm` 未锁定** —— `.locked()` 在 `acx750_top.sv` L507 **悬空**，失锁完全静默（无 LED、无 UART 位、无报告）。

2. **MMCM 外反馈（`u_eth_feedback` BUFG）改变了 IDDR 处时钟相位**：RGMII RXD 相对 RXC 的采样窗口被破坏 → 采样错位 → 帧全废 → 过滤器全拒 → `eth_pkt_done` 永不触发。

3. RTL8211F 内部 RX delay 与新时钟树的建立/保持关系不匹配。

# 千兆网口 RX 修复

## 板测依据与更正

上板逐项测试已经确认：相同板卡、网线和电脑直连 1 Gbps，厂商 ch52 镜像 20/20 回环逐字节匹配，通信版原 HDMI 镜像 E0。硬件及链路协商不是首轮重点。

进一步只读提取厂商 200t ch52 的顶层、io.xdc 和 clk_wiz_0.xci 后，发现测试记录中的“厂商 RXC 直接 BUFG，无 MMCM”描述不准确。厂商顶层例化 clk_wiz_0，配置 `CLKOUT1_REQUESTED_PHASE=90`、125 MHz；现行 eth_phase_mmcm 为 0 度。实际采样相位不一致是修复重点，但最终根因仍需新镜像板测确认，不能把推断写成实测。

参考原件位于厂商配套 `200t/ch52_acx750_eth_udp_loopback.rar`，提取的少量只读诊断副本位于 `vivado_project/logs/eth_rx_fix_20261002/vendor`，原件未修改。

## 改动与编译前结构审查

- 两套现行工程 eth_phase_mmcm 改为 125 MHz、90 度输出，保留 No_buffer 和当前唯一输出 BUFG；通信版 BUFG 仍在厂商 UDP 接收器内部，Full 仍为顶层唯一 BUFG。不增加第二个输出 BUFG。
- 不改厂商 eth_udp_rx_gmii.v 或 IDDR 解码协议，不重写已经存在的 ARP/UDP 功能。
- MMCM 启用系统复位，locked 不再悬空。接收域复位要求系统复位释放、DDR 校准与 RX MMCM 锁定；通过现有双触发器复位同步器释放给 IDDR 和两类 UDP 接收器。
- locked 用两级 CDC 同步到系统域；LED1、UART/HUD 的 P 状态现在表示系统时钟和 RX 时钟都锁定，E 仍表示有效接收活动。无网线/RXC 时 P 可以为 0，但 HDMI 不因此停止。
- DDR 写侧继续通过现有 XPM 异步 FIFO 到固定 100 MHz，不恢复旧多路写时钟 MUX。
- HDMI、按钮、像素流水线、雷达算法及存储结构不变。新增状态 CDC 仅两级寄存器和少量门，不增加大型 MUX、宽总线、乘除法或存储；预计资源变化小，实际以综合报告为准。
- 90 度即 125 MHz 时钟周期内约 2 ns 的采样位置变化，不降低吞吐。启动/恢复时额外等待锁定和两拍复位释放；正常逐包/逐点及视频流水线不增加拍数。
- 不降频，不加错误 false_path/multicycle。现有外设时序覆盖限制仍保留，理想仿真不是 PCB 眼图验证。

## 回归与发布门限

新增 `test_eth_rx_phase.tcl` 验证 Clock Wizard 的实际仿真输出、90 度采样、RGMII 字节/RX_CTL、DDR 未就绪、复位和重新锁定；沿用 13 组 UDP A/B 协议回归。首次自检在复位释放的 IDDR 空流水线阶段误比较，修正为等待两级捕获生效，不为通过测试修改 RTL。

还须运行既有 HDMI/按钮与 CDC/FIFO 测试，整机构建使用 build_hdmi_pair.py 和统一图形监视器。最终 WNS/WHS 非负、DRC_BAD=0 后生成候选 bit。

候选源码哈希现在包含 XCI：IP 相位也是完整设计的一部分，不能只核对 RTL/XDC。旧 manifest 未包含 XCI 且源码已变化，因此旧候选不再通过加载检查；新镜像必须重建并生成新 manifest。

当前状态：修复源码与 IP 更新完成；回归与构建结果待本轮填入，不宣称网口已经实板恢复。

## 新镜像板测

先通信版，后 Full；首次 JTAG 临时加载。直连 1 Gbps 下先观察 P=1，再运行 rx_direct_probe，检查 E、ARP 应答与 M3TL 心跳/CRC/序号；再恢复交换机重复。ARP 是必要项，当前实现是否响应 ICMP ping 需独立确认，不能把不响应 ping 单独判为 ARP 失败。

若 P=0，查 RXC/锁定；P=1 仍 E0，抓取 GMII DV/数据/CRC 与采样窗口再定位。MID-360 在网络验收后接入，允许上电 12 秒无数据。重新检查 HDMI、按钮和 DDR，保证不回退。
