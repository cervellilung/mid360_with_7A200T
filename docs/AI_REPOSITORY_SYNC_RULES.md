## 4. 每次开始工作的同步流程

1. 检查目录、分支、远端和本地修改：`git status --short --branch`、`git remote -v`、`git log -5 --oneline`。
2. 执行 `git fetch origin`，检查 `origin/main` 是否有新提交；阅读远端变更后再开始依赖这些文件开发。
3. 有未提交或未推送的本地修改时，先逐项识别所有者和内容。不得 `reset --hard`、`clean -fd`、覆盖文件、强制切换分支或静默丢弃修改。
4. 本地干净且远端仅为向前更新时，可用 `git pull --ff-only origin main`。若有冲突，保留双方有效内容；含义不明确时停止冲突文件的覆盖操作并向用户报告具体冲突。

## 5. 修改、提交与推送流程

1. 只在当前项目目录内按任务修改；不修改 `可研` 原目录，不恢复整个 `旧项目`。
2. 文档用中文维护；更新方案、验证结果或交接时，记录证据、尚未验证的部分、遗留问题和下一步。
3. 优先按文件/目录明确暂存，避免未审查的 `git add -A`。暂存后检查 `git status`、`git diff --cached --stat`、`git diff --cached --name-only` 和 `git diff --cached --check`。
4. 提交前检查暂存区：没有密钥/密码、用户隐私、原始录制、构建产物、整套旧工程或不必要的大文件；确认每个新增参考资料都有来源说明。
5. 仅当用户明确要求提交、上传或同步时，才创建提交并推送到 `origin/main`。普通代码开发默认保留本地改动并报告，不自行发布。
6. 禁止对共享分支执行 `push --force`、重写公共历史或删除远端文件来绕过冲突。
7. 推送后读取远端 `main` 的提交号，并检查本地 `main` 与 `origin/main` 一致、工作区状态符合预期；向用户报告提交号、文件范围、排除项和验证状态。
