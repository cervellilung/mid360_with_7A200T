# ACX750 上位机（树莓派 5）

从 ACX750（XC7A200T 纯 FPGA，无 ARM PS）的 PL 直接通过以太网 UDP 接收低带宽遥测结果，
落盘为会话记录并在本地网页查看。

> 与旧工程（AC880 / Zynq）最大的区别：**不再通过 TCP 从 PS 拉流，而是直接 UDP 从 PL 收包**。
> 协议是 `docs/telemetry_protocol.md` 里的 M3TL v1（本目录按新口径实现，含新增的 55×60 栅格）。

依赖：**仅 Python 3 标准库**，无需 `pip install`（现场可能无外网）。
requirements：无第三方依赖；若以后引入，请在此列出。

## 目录内容

| 文件 | 作用 |
|---|---|
| `m3tl.py` | M3TL v1 协议层：帧打包/解包、双 CRC 校验、各类型载荷编解码、栅格位图 |
| `server.py` | UDP 接收服务 + 只读 HTTP 状态接口（网页数据源） |
| `recording.py` | 会话落盘：`telemetry.jsonl` 与 `summary.json` |
| `viewer.html` | 中文可视化网页（无 CDN）：栅格俯视图、目标列表、心跳灯、缺口统计 |
| `replay.py` | 离线回放：按时间戳节奏把 JSONL 重发为 UDP 帧 |
| `config.example.json` | 配置模板 |

## 快速开始

在仓库根目录执行（或 `cd` 到本目录后去掉路径前缀）：

```sh
# 1) 只接收，不落盘，网页开在 8765
python3 fpga_acx750/host/server.py

# 2) 带会话落盘（写入 sessions/demo/）
python3 fpga_acx750/host/server.py --session demo

# 3) 用配置文件 + 改端口
python3 fpga_acx750/host/server.py --config fpga_acx750/host/config.example.json --port 46000

# 4) 浏览器打开（树莓派本机或同网段电脑）
#    http://<树莓派IP>:8765/
```

主要命令行参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--bind` | `0.0.0.0` | UDP 监听地址 |
| `--port` | `46000` | UDP 监听端口（与 PL 发送目标一致） |
| `--web-bind` / `--web-port` | `0.0.0.0` / `8765` | 网页服务地址与端口 |
| `--session` | 无 | 会话名，**指定后才落盘** |
| `--session-dir` | `sessions` | 会话根目录 |
| `--config` | 无 | JSON 配置文件 |
| `--no-record` | 关 | 只接收不落盘 |

## 协议要点（实现口径）

* 32 字节帧头，全小端；`header_crc32` 对偏移 0..23，`payload_crc32` 对载荷，均与 `zlib.crc32` 一致。
* 接收端严格校验：UDP 载荷长度必须等于 `32 + payload_len`，magic 正确，两个 CRC 正确；否则丢弃并计数。
* 消息类型：`1` 心跳、`2` 底盘、`3` 目标、`5` 栅格（55×60，413 字节位图）、`6` 相机状态。
* 未知 type 不报错：按 `payload_len` 跳过并计一次 unknown。
* 栅格位序：行优先，第 `r*cols+c` 格对应 `byte[(r*cols+c)//8]` 的 `bit((r*cols+c)%8)`（LSB 在前）。

## 会话记录格式

```
sessions/<name>/
├── telemetry.jsonl   每行 {"type","seq","t_ms", ...解码字段}
└── summary.json      每类型包数、CRC 坏包、序号缺口、首末时间戳、时长
```

`telemetry.jsonl` 追加写入（重启同一会话不覆盖历史）；`summary.json` 在进程退出时重写，
描述本次运行。

## 离线演示（无硬件时）

```sh
# 终端 A：起接收端（会打印网页地址）
python3 fpga_acx750/host/server.py --session replay_demo

# 终端 B：回放一段会话（倍速/区间可调）
python3 fpga_acx750/host/replay.py fpga_acx750/host/sessions/replay_demo/telemetry.jsonl --speed 1.0
```

`replay.py` 由 JSONL 里的解码字段重建载荷，再打包成 M3TL 帧发给接收端。
因未知类型无法重建，会被跳过并计数。

## 自检与联调

```sh
# 协议自检（标准库，无依赖），应打印 PASS
python3 fpga_acx750/tests/test_m3tl.py
```

联调步骤：

1. 确认树莓派与 PL 同网段（历史地址：板端 `10.42.0.2/24`、上位机 `10.42.0.1/24`，以现场为准）。
2. 启动 `server.py`，网页应显示“已连接”，各通道延迟开始刷新。
3. 若某通道一直无数据，先确认 PL 发送的目标 IP/端口与 `--bind/--port` 一致，再用 `tcpdump -i eth0 udp port 46000` 抓包定位。

  | type | 名称 | 载荷 |

## 会话记录格式

```
sessions/<name>/
├── telemetry.jsonl   每行 {"type","seq","t_ms", ...解码字段}
└── summary.json      每类型包数、CRC 坏包、序号缺口、首末时间戳、时长
```

`telemetry.jsonl` 追加写入（重启同一会话不覆盖历史）；`summary.json` 在进程退出时重写，
描述本次运行。

**GRID（type=5）落盘瘦身**：413 字节位图**不逐字节塞进 JSONL**（否则每帧多出上千字符），
而是落 `occupied_count`（占据格数）+ 可选的 `bitmap_b64`（413 字节位图的 base64 单串，
约 552 字符）。选 base64 而非独立二进制侧文件的原因：JSONL 自包含、可直接被 `replay.py`
回放，不需要额外的偏移表/对齐逻辑，实现更简单、出错面更小。若不需要回放栅格，可用
配置文件里的 `"grid_bitmap": false` 只保留 `occupied_count`（此时回放会跳过栅格帧）。

## 下行配置（上位机 → PL）

`cfg_client.py` 把配置读写命令经 UDP 发给 PL 控制面，落到 PL 侧 `perception_regs`
（4 KiB AXI-Lite 页）的寄存器上。接口定义以 PL 侧
`fpga_acx750_full/docs/control_plane_750.md` 为准；撰写本文件时该文档尚不存在，
故先按下列口径实现，**待该文档落地后需回来对齐**。

**网络层现状**：PL 是单口 PHY，但**内部按 IP/端口分流**，已具备**两个独立的 UDP 服务
端口**——`56301` 收 MID-360 点云、`56300` 收树莓派下行配置；上行遥测走 `46000`，
ARP 由 PL 应答。因此下行配置**无需 magic hack**，直接以 opcode 开头即可
（我们自研的 UDP 接收器不带内部 `BUFG`，可以放两个独立端口）。
现场需用**一个二层交换机把雷达 / 树莓派 / PL 连到同一网段**。

UDP 载荷（全小端）：

| 偏移 | 字段 | 说明 |
|---:|---|---|
| 0 | opcode u8 | `0x01` 写单字、`0x02` 读单字、`0x03` 批量写、`0x04` 触发快照读 |
| 1 | count u8 | 仅 `0x03` 用（1..16），其余填 1 |
| 2-3 | reserved | 0 |
| 4.. | count 组 | 每组 `word_index:u16`，然后（仅 0x01/0x03）`value:u32` |

`word_index` 是 32 位字地址（`0x000..0x3FF`），**AXI 字节地址 = word_index×4**，
例如 word_index `0x40` ↔ 字节地址 `0x100`。目的端口已做成 `--port` 参数（默认 `56300`），
将来端口调整无需改代码。

### 用法示例

```sh
# 写单字：把配置区首字（word 0x40，字节 0x100）写 0xDEADBEEF
python3 fpga_acx750_full/host/cfg_client.py --write 0x40 0xDEADBEEF

# 读 ID（word 0x000），等 PL 的 M3TL type=7 应答；超时会报错
python3 fpga_acx750_full/host/cfg_client.py --read 0x0

# 批量写两个配置字
python3 fpga_acx750_full/host/cfg_client.py --batch 0x40=1 0x41=2

# 触发快照读
python3 fpga_acx750_full/host/cfg_client.py --snapshot

# 自定义地址/端口/超时（端口默认 56300，可覆盖）
python3 fpga_acx750_full/host/cfg_client.py --host 192.168.1.50 --port 56300 --timeout 1.5 --read 0x2
```

`read_word()` 在同一个 socket 上收包解出 `type=7` 应答，超时抛 `CfgTimeout`。
**注意**：`type=7` 属 PL 侧待实现，目前排空可能收不到应答。

### 配置字索引参考表（word_index 口径）

源自 PL 侧 `rtl/perception/perception_regs.sv` 的寄存器映射，`word_index×4 = AXI 字节地址`：

| 区域 | word_index 范围 | AXI 字节地址 | 数量 | 说明 |
|---|---:|---:|---:|---|
| ID | `0x000` | `0x000` | 1 | 只读，恒为 `0x31524550` |
| 状态序号 | `0x001` | `0x004` | 1 | 只读，快照序号 `seq` |
| 状态 | `0x002` | `0x008` | 1 | 读：bit0=`config_pending`，bit1=`snapshot_busy`；写：bit0=1 置 pending |
| 配置区 | `0x040..0x07F` | `0x100..0x1FF` | 64 | 可写 shadow 配置字（提交后生效） |
| LUT 区 | `0x100..0x1DC` | `0x400..0x773` | 221 | 可写 LUT |
| 快照区 | `0x200..0x39F` | `0x800..0xE7F` | 416 | 只读快照内容 |

> 区域上界按字节地址给（配置区 `0x100..0x1FF`、LUT `0x400..0x773`、快照 `0x800..0xE7F`），
> 换算成 word_index 即上表。**word_index 是 32 位字地址，不是字节地址。**

### 地图与性能边界

局部地图最多配置40000点，Odom队列/场景队列有界；默认外参和时间未确认时只保存局部可见场景。合法Odom不等于安装外参/时间已经标定。位姿跨越、时间异常或过期会暂停融合，不能把自由视角或静态融合当作移动轨迹。

本轮60秒负载为160×128RGB565、30fps（视频2400包/s），并叠加雷达100Hz16点包和Odom20Hz；收到并存档151319包，1800完整视频帧，CRC零错误，两次回放一致。**1024×600网络视频、Pi5软件编码、长时间磁盘写入与WebRTC端到端延迟仍待测试**，不能推导为已实现30fps满分辨率。


满尺寸诊断补充：`--duration 5 --width 1024 --height 600` 在本机同时运行Vivado时只生成35帧（约7fps），84080个包全部收录，22帧完整、13帧组帧超时，CRC零错误。sender自身也未达到目标速率，不能把这个结果当接收端独立最大fps。工具已支持尺寸/fps参数，Pi5板测应使用真实FPGA源测量；若达不到25/30fps，优先量测单实例接收CPU与包率，再考虑批量收包或较大分片，不能通过无界队列积压旧帧。

### 网络视频首轮尺寸修正

活动Full输出512×300 RGB565（HDMI1024×600保持原样），采用常量2×2抽样降低有效行突发。Linux按M3VP头自动接收并为编码器建立对应尺寸，不把它标成1024×600。模块DECIMATE=1仅作为离线对照；恢复全分辨率需增加吞吐/缓冲方案并重新验证。媒体线程最多30fps取最新完整帧，不能据此声称Pi5已经实测30fps。

独立视频失锁复位限制：M3VP-v1依赖HB uptime回退识别板卡整体重启；仅视频域重启、HB继续单调时，没有独立时代字段。停止当前录制、重启服务并用新会话接收；不要自动接受更旧的帧号。该恢复方式未在板卡失锁场景实测。

### 候选实现

`planar_mesh.py` 固定种子77，RANSAC候选由当前窗口抽样产生，再用该窗口全部有效点稳健重拟合。默认残差20 mm＋距离每米1 mm，最低平面支持600点，最多8平面。每个平面建立二维坐标系，10 mm UV单元保留一条原始测量去重，全部原始点参与拟合和视线门禁；原始XYZ始终保留。显示坐标投影到平面，P95调整约9～10 mm，最大约31 mm，会磨掉阈值内的小凸起，不能称原始坐标没有变化。

Delaunay只生成候选；随后用3.2°角上限、六邻居局部尺度、连接系数2.8、空间连通分量（至少30点）、七个三角内部/边界探针及回波一致性筛选。同平面仍分局部空间区域；断开的对象不因共面而连成整片凸包。支持较弱的小孔只有探针邻域呈环绕支持、到支持点距离不超过0.20m等条件成立才标为推断补面。橙色是几何支持分类，不是真值。

视线检验沿实际观测射线计算与拟合平面的交点距离，与该射线实测距离比较；近遮挡、远穿透都可拒绝，避免仅凭斜面的径向距离差误断开。没有对应射线不等于证明实心；真实小开口与采样缺口仍无法完全区分。

平面之间分别生成显示顶点和法向，未强制90°，未自动添加交线顶点。保留角度算法的未归类复杂面作为回退；跨已拟合平面的面保守移除。边界因分面而可能有裂缝。`inspection.json`给出实际拟合夹角和有限双侧支持区间的边界距离上界；这些上界不是实测裂缝宽度，不作为自动拼接证据。
