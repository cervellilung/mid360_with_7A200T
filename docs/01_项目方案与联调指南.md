## 2026-10-08 双摄与底盘接线分工修正

ACX750唯一40Pin由OV5640_DUAL占用；不得继续照旧方案接底盘UART。相机未使用的GPIO32–35是否被转接板实际引出尚未核实。当前方案为750承担双摄/深度/HDMI/AR，AC880 PL承担底盘UART与速度/里程处理，经网络送750和树莓派。底盘支路不依赖AC880不存在的PL DDR；消息需带序号、时间戳、有效性和错误计数，超时撤销有效状态。跨板接口和真实底盘均待实现/验收。

N10按最新指示暂停。双摄只算一类传感器，两类传感器及两项FPGA处理的完整验收须等底盘链路完成。官方双摄以太网参考位于`routine/references/acx750_dual/ch54_acx750_ov5640x2_udp_rgmii`。

## 2026-10-08 当前开发决定：双目基础链路与进阶接口预留

以本节覆盖旧章节中的架构与开发优先级：采用小梅哥 OV5640_DUAL、镭神 N10、ACX750/7A200T、AC880/7020 和树莓派5。当前先开发750赛题基础链路，AC880先预留接口，识别、N10定位/SLAM及其他进阶功能后期实施。不再研究单板容纳全部功能。AC880没有PL DDR，大容量PL缓存只能经AXI HP使用PS DDR；不得引用旧工程中假定存在PL DDR的帧缓存。

# MID-360 + XC7Z020 方向三：当前项目方案

> 此文件保留 2026-09-29 较早阶段方案；最新实测、问题与工程目录以[项目总交接](项目总交接.md)为准。

更新：2026-09-29。本文件放在 `AI_HANDOFF.md` 所在目录，作为**当前执行方案**。早期交接材料中的“OV5640 → PL DDR3”“PS 裸机 lwIP”“HDMI 主显示”等是旧方案；本阶段改用 USB 摄像头、PS Linux、PS DDR 与 5 寸 TFT。`可研` 目录仅作历史资料，不修改。

## 1. 目标和交付边界

目标是以 AC880/XC7Z020 板卡为现场核心，融合 MID-360、USB 全局快门摄像头和底盘 Odom/IMU，完成实时障碍物感知、距离与风险提示、TFT 红青 AR/车辆状态显示，并并行完成多视角场景重建与数字孪生。**红青 AR 和多视角数字孪生是两项交付，互不替代。**

分两层实施：

1. **当前采集基线**：先把三路真实原始数据可靠录到电脑或树莓派，建立时间戳、CRC、序号、断流与回放证据，用这些数据优化算法和标定。此阶段只是开发基础，不等于赛题最终演示。
2. **最终现场演示**：关键雷达感知、底盘状态处理、目标投影/风险判断和红青 AR 画面必须在 FPGA/板卡现场链路中实现并实测；树莓派 5 承担位姿融合、多视角配准、表面重建、网页与存储。USB 摄像头经 PS Host 接入后，须用实测与赛题条款复核最终硬件分工；不能因能录制视频就声称 FPGA 视觉/AR 要求已满足。

## 2. 当前硬件与连接

| 部件 | 连接与作用 | 当前状态 |
| --- | --- | --- |
| MID-360 | 独立供电，RJ45 到交换机/板卡 PL 网口；PL `192.168.1.50:56301` 接收雷达 `192.168.1.20` 数据 | 当前未接板卡；雷达启动允许约 12 秒无包 |
| USB 全局快门摄像头 | PS USB Host1；首轮目标 640×480 YUYV 30 fps，120 fps MJPEG 需实测 | USB 已枚举，厂商 Linux 缺 UVC，尚无 `/dev/video0` |
| DFLink 底盘 | PL 40Pin：P7-39/W6 → 底盘 RXD；P7-40/W5 ← 底盘 TXD；P7-28 ↔ GND；底盘独立供电 | 真实 Odom 尚未在本工程验证；接线前复核底盘 TX 空闲高电平约 3.3 V，不接 P7 电源脚 |

摄像头镜头朝雷达 `+X`，成像面竖直，安装位置约在雷达前方 9 cm；这只是外参初值，两个光学中心的实际偏移、相机滚转及内参仍需标定。详见 `fpga_ac880/sensor_capture_linux/CAMERA_MOUNT_NOTES.md`。

## 3. 当前采集基线的数据路径

```text
MID-360 → PL RGMII/ARP/UDP → 原始包固定槽(2048 B) → AXI DMA → Linux 字符设备
底盘 UART → PL Odom v4 校验 → 固定槽(64 B) → AXI DMA → Linux 字符设备
USB 摄像头 → PS USB Host/UVC/V4L2 → 最新完整 YUYV 帧 → PS DDR
                                                   ├→ Linux /dev/fb0 → VDMA → TFT
三路 Linux 采集 → M3CP-v1 TCP 46101/46102/46103 → PC/树莓派录制与确定性回放
```

两路 PL 数据由 DMAengine 客户端交付完整定长记录，长度前缀避免依赖提前 TLAST 的 residue。Linux 端只保留有界缓冲和最新相机帧，慢接收端不能积压旧画面。原始包/帧连同时间戳、序号、CRC 存档；显示与算法消费同一可回放数据。现有厂商 `/dev/fb0` 为单页 800×480 RGB565，需测撕裂、帧率和延迟。所有相机视频缓存位于 **PS DDR**，不再假设板上存在可用的 PL DDR 帧缓存。

工程位置：`fpga_ac880/sensor_capture_linux/`。它独立于旧 `sensor_capture_ps/` 和厂商原工程。协议、脚本与测试入口见该目录的 `README.md`。

## 4. 最终算法与展示分工

| 层 | 目标职责 | 当前完成度 |
| --- | --- | --- |
| PL 雷达感知 | MID-360 校验/组帧、定点地面过滤、55×60 有界栅格、4 邻域连通域、最多 32 个目标、距离/风险 | 整数 PC 参考模型已有；最终 PL 算法尚未接入 Linux 采集镜像 |
| PL 底盘状态 | Odom v4、速度/里程/IMU 状态，断流无效化 | 帧接收路径已集成；真实底盘和完整姿态算法未验收 |
| 板卡视频/AR | 相机帧进入 PS DDR，经 PL 视频链路到 TFT；定点投影、红青视差、目标框、HUD、失效撤框 | 红青叠加 RTL 独立仿真/综合通过；尚未接入最终视频块图，标定未完成 |
| PS Linux | UVC/V4L2、DMA 取数、控制与限长转发、现场显示桥接 | 用户程序已交叉编译；UVC 驱动与 DMA 内核模块尚未板测 |
| 树莓派 5/电脑 | 原始数据录制回放、离线标定、位姿融合、运动补偿、多视角表面重建与网页数字孪生 | 电脑端早期固定雷达预览已有；移动车辆、多视角闭环未完成 |

实时感知按雷达扫描周期输出；超过 150 ms 的旧障碍物结果撤下。地面、栅格和投影参数可离线浮点标定，运行核心按 FPGA 约束采用整数/定点参考模型。数字孪生在运动状态必须使用真实 Odom/IMU 位姿和运动补偿；早期静止雷达的平滑网格不能作为最终成果。

## 5. 已验证事实与当前阻塞

- **实板已验证**：旧 TFT 彩条；厂商 Ubuntu 从 TF 启动；PS 千兆网口 PowerShell SSH；摄像头在 USB 总线枚举。以上均不证明新采集镜像可录制三路。
- **离线已验证**：60 秒合成三路录制/回放、协议 CRC/序号；两个独立 RTL 模块仿真；新集成工程综合与路由。新 bit/XSA 已生成，路由后 WNS `+0.538 ns`、WHS `+0.036 ns`，DRC 0 Error、0 Critical Warning。
- **未上板**：新 bit、两路 AXI DMA、真实 MID-360 和 Odom、TFT 新视频链路、三路 TCP 录制。红青 AR 和多视角数字孪生均未完成。
- **首要阻塞**：厂商内核 `5.4.0-xilinx-v2020.2` 的 `CONFIG_MEDIA_USB_SUPPORT` 未启用，且无 `/lib/modules`，所以无 `/dev/video0`；本地已有 4.14 内核源码不能直接编给 5.4。新 PL DMA 也需匹配内核的驱动与设备树。板上 PS IP 临时设置还未持久化。

## 6. 下一步执行顺序

1. 在本地资料中找与板上 5.4 内核**同一构建**的源码/配置；完成 UVC 与 DMA 驱动、设备树的可回退构建方案。没有匹配源码时记录阻塞，不把不兼容模块强行加载。
2. 对照新 XSA 和厂商运行设备树核查 PS、USB、VDMA 地址/中断/时钟；备份板上配置后，用 JTAG 临时加载新 bit 验 TFT/PL 接口。先不替换 TF `system.bit`。
3. 单独录制相机、底盘、MID-360，各 10 秒并检查格式、CRC、序号、时间戳、断流；MID-360 重上电要覆盖约 12 秒初始化。需要重新连接雷达或复核底盘电平时再通知用户。
4. 三路同时录制至少 60 秒，测相机帧率、最大帧间隔、DMA/FIFO 溢出、网络重连和可重放性。用**真实录制数据**优化整数感知与固定点向量。
5. 标定相机内参、雷达—相机外参、地面与时间偏差；集成 PL 红青 AR/TFT 并测现场延迟；并行接入真实 Odom/IMU 位姿，完成树莓派多视角数字孪生。

详细过程与遗留问题：`fpga_ac880/sensor_capture_linux/PROJECT_HANDOFF.md`、`BOARD_VALIDATION_STATUS.md`、`LONG_RUNNING_ISSUES.md`。电脑远程操作板卡使用 PowerShell `ssh`，不使用 MCP SSH。额度任一适用窗口仅剩 5% 时停止新工作并更新上述交接/问题记录。

## 1. 设计原则与赛题边界

赛题要求指定 PLD 开发板作为设计核心，关键感知或显示数据通路必须在 FPGA 中实现，不能把 FPGA 只作为视频直通或简单 I/O 桥；方向三还要求 FPGA 完成至少两项传感器处理、AR 叠加和车辆状态可视化。

因此树莓派 5 作为协处理器使用，承担建图、配准、网页和存储等不适合 XC7Z020 的重任务。即使拔掉树莓派，FPGA 仍必须独立完成：

1. OV5640 实时采集和 TFT 显示。
2. MID-360 包解析、地面过滤、栅格障碍物检测、距离和风险判断。
3. DFLink Odom v4 解析、编码器速度/里程处理和 IMU 定点姿态解算。
4. 摄像头、雷达和 Odom 的统一时间戳。
5. 障碍物、距离、速度、航向、风险信息的 AR/红青立体叠加。
6. 基本俯视车辆状态显示以及雷达或树莓派掉线提示。

这使 FPGA 独立覆盖方向三基础要求。树莓派上的多视角数字孪生、远程监控和参数面板属于拓展功能。

## 2. 硬件连接

```text
MID-360 ──RJ45──> XC7Z020 PL 千兆网口
OV5640  ──DVP───> XC7Z020 PL
DCar    <─TTL UART─> XC7Z020 PL 40Pin（39/40/28，FPGA 侧为 3.3 V）

XC7Z020 PL ──PL DDR3──> 视频帧缓存
XC7Z020 PL ──5寸 TFT RGB565──> 现场 AR/红青显示器

XC7Z020 PL ──AXI DMA/AXI-Lite──> Zynq PS
Zynq PS     ──PS 千兆网口──> 树莓派 5 千兆网口
树莓派 5   ──Wi-Fi──> 浏览器/调试电脑
```

固定网络规划：

| 链路 | 地址 |
| --- | --- |
| MID-360 | `192.168.1.20/24` |
| FPGA PL 雷达接口 | `192.168.1.50/24`，点云端口 `56301` |
| 树莓派 5 有线口 | `10.42.0.1/24` |
| Zynq PS 有线口 | `10.42.0.2/24` |
| 树莓派 Wi-Fi | 接入现场网络或建立热点，不与上述两个网段重号 |

### 2.1 底盘串口最终预留

底盘采用 AC880 的 PL GPIO 40Pin 接口，不占 PS 串口，也不经过树莓派。按板卡用户手册的 P7 排针编号，固定使用：

| AC880 P7 物理针 | 板卡信号 | XC7Z020 管脚 | 方向 | 接到底盘 |
| --- | --- | --- | --- | --- |
| 39 | `PL_GPIO0_34` | `W6` | FPGA 输出 | DCar `RXD` |
| 40 | `PL_GPIO0_35` | `W5` | FPGA 输入 | DCar `TXD` |
| 28 | `GND` | — | 公共参考 | DCar `GND` |

接线必须交叉：`W6/TX → DCar RXD`，`W5/RX ← DCar TXD`，并共地。只接这三根线；不从 P7 的 5 V 或 3.3 V 针脚给底盘供电。Vivado 实现报告已确认 W6/W5 位于 PL Bank 13 且约束为 `LVCMOS33`。这不能代替 DCar 侧电压核对：接线前按 `https://differ-tech.pages.dev/` 中对应车型资料或用万用表确认 DCar TX 高电平；若为 5 V，必须在 DCar TXD 到 FPGA W5 之间加电平转换器。

5 寸 TFT 使用板卡独立 TFT 接口的 `V22/AB19/U19/AB14/U14` 和 RGB565 数据脚，不占用 P7 的 `W6/W5`，因此 TFT 与底盘 UART 可以同时工作。板载 `PL USB 转串口` 的 `P15/N15` 保留为电脑调试口，不连接底盘。

串口参数及 DFLink 固定值来自旧项目 `chesai_car`：

| 项目 | 值 |
| --- | --- |
| 串口 | `460800 baud, 8 data bits, no parity, 1 stop bit` |
| DFLink 帧 | `DF target source A B LEN payload FD sumL sumH` |
| 地址 | 底盘 `target=0x01`，上位机/FPGA `source=0x97` |
| 校验 | 从 `0xDF` 到 `0xFD` 全部字节累加，取低 16 位，小端发送 |
| Odom 订阅 | `A=0x04, B=0x80`；连续模式 payload=`01`；50 Hz 枚举值=`05` |
| Odom v4 回传 | `A=0x6C, B=0x80`，payload 51 字节，首字节版本 `04` |

50 Hz 连续订阅的完整发送帧为：

```text
DF 01 97 04 80 02 01 05 FD 00 03
```

末两字节 `00 03` 是累加和 `0x0300` 的小端表示。PL UART 接收器先按帧头和 `LEN` 找边界，再检查帧尾和校验；只有完整合法帧才能更新速度、里程和姿态。底盘掉线超过 150 ms 时，状态置为无效并在 TFT HUD 显示掉线。

对应约束文件为 `fpga_ac880/constraints/chassis_uart.xdc`。

## 3. 功能拆分

### 3.1 FPGA PL：不可替代的实时核心

| 模块 | FPGA 内实现内容 | 输出 |
| --- | --- | --- |
| 雷达网络前端 | RGMII、ARP、IPv4/UDP、MID-360 上电配置与点云接收 | 原始包、包状态 |
| 雷达感知 | 100 ms 组帧、定点地面过滤、55×60 栅格、4 邻域连通域、最多 32 目标 | 障碍物表、距离、风险 |
| 车辆状态 | DFLink 帧校验、速度/里程计算、IMU CORDIC 与互补滤波 | 速度、位置、姿态 |
| 时间同步 | 100 MHz 统一单调时钟，在 VSYNC、雷达包和 Odom 帧边界锁存时间 | 64 位时间戳 |
| 视频 | OV5640 SCCB、DVP 采集、PL DDR3 帧缓存、800×480 TFT 显示 | RGB565 像素流 |
| AR/3D | 定点雷达相机投影、框线、距离、风险、HUD、红青视差 | TFT 现场画面 |
| 基础状态显示 | 小型俯视图、车辆标记、航向、速度、链路状态 | TFT 可视化 |
| 对外数据流 | 原始雷达包、Odom、目标表、健康状态、低帧率预览分流 | AXI Stream |

FPGA 上明确保留的两项以上传感器处理为：

- MID-360 障碍物检测、距离和风险判断。
- 编码器速度/里程处理。
- IMU 定点姿态解算。

### 3.2 Zynq PS 双核：只做轻量搬运

PS 不运行 OpenCV、PCL、SLAM、网格重建或 Web 服务。首版使用 Vitis 裸机和 lwIP，仅启用 Cortex-A9 Core 0，Core 1 保留。

PS 任务固定为：

1. 初始化 AXI DMA 描述符环和 AXI-Lite 参数区。
2. 将 PL 产生的数据块通过 PS 千兆网口转发给树莓派。
3. 接收树莓派参数命令，校验范围后写入 PL 寄存器。
4. 维护序号、CRC、心跳、断线重连和统计计数。
5. 上报 DMA 溢出、网络断线和 PL 模块状态。

PS 不修改检测结果，不参与 AR 生成。树莓派断线后 PS 丢弃待转发数据，不能阻塞 PL 实时链路。

### 3.3 树莓派 5：高层计算和展示

树莓派承担：

1. 兼容电脑端格式的完整数据录制与确定性回放。
2. 雷达、IMU、编码器时差估计和运动补偿。
3. Odom/IMU 融合、雷达扫描匹配和位姿图优化。
4. 关键帧管理、体素地图、可见表面重建和地图保存。
5. 数字孪生服务：车辆模型、轨迹、障碍物、风险区和场景表面。
6. 浏览器参数面板、状态监控和数据下载。
7. 浮点标定计算，并将定点参数下发给 FPGA。
8. 低帧率视频预览；现场主显示仍由 FPGA TFT 输出。

树莓派不得代替 FPGA 生成最终 AR 框、风险判断或 TFT 画面。它可以把优化后的车辆位姿和地图摘要返回 FPGA，FPGA只把它们作为附加显示信息。

## 4. PL—PS—树莓派接口

### 4.1 PL 到 PS

- AXI DMA S2MM 使用 8 个 64 KiB 描述符组成循环缓冲。
- PL 聚合数据后再触发块完成，避免每个雷达包产生一次 ARM 中断。
- AXI-Lite 提供版本、状态、计数器、配置参数和最近 32 个障碍物的只读镜像。
- DMA 堵塞时只丢弃树莓派分流副本并增加计数，不影响栅格感知和 TFT。

### 4.2 统一遥测帧

当前电脑、PS 和后续树莓派统一使用 `docs/telemetry_protocol.md` 定义的
`M3TL` version 1 小端 UDP 数据报：32 字节头、序号、毫秒时间戳、头 CRC32
和载荷 CRC32，单报文最大 1056 字节。已固定的消息为 heartbeat、chassis、
最多 32 个 targets 和 camera status。MID-360 原始包、DFLink 原始帧、预览帧
及树莓派参数回写将在对应 PL/AXI 数据源完成后增加版本化类型，不能继续使用
旧草案中的 `GFPM` 头。

### 4.3 PS 到树莓派

- PS 从 `10.42.0.2` 向 `10.42.0.1:46000` 发送有界 UDP 遥测；电脑联调和后续树莓派使用同一接收协议。参数回写通道在确有需要时再增加，当前 PS 不维护 TCP 会话。
- 电脑或树莓派按 `docs/telemetry_protocol.md` 解析数据报，并根据序号、CRC 和时间戳检查丢包及旧数据。
- 每个数据报独立解析；接收端断开或未启动不会阻塞 PS，也不会拖慢 PL。

### 4.4 视频预览

PL 将 800×480 像素按 2×2 抽样为 400×240 RGB565，默认 5 fps 送往树莓派。该预览用于标定、网页监控和截图，不参与最终 TFT 显示。

## 5. 分阶段联调

### 阶段 A：各板独立

1. FPGA：TFT 色条、PL 以太网回环、OV5640 到 TFT。
2. 树莓派：系统、SSH、有线静态 IP、Wi-Fi 和存储速度。
3. 我负责生成命令、配置和测试程序；需要烧录镜像、插线、选择网卡或观察 LED 时再让用户操作。

### 阶段 B：FPGA 基础闭环

1. PL 直收 MID-360 并输出障碍物。
2. PL 接收 Odom v4 并输出速度、里程和姿态。
3. OV5640 画面上叠加雷达距离、风险、速度和航向。
4. 拔掉树莓派验证 FPGA 基础功能完全正常。

### 阶段 C：PS 转发

1. 用合成 AXI 数据验证有界 UDP 遥测和序号/CRC。
2. 转发真实雷达、Odom、障碍物和健康状态。
3. 通过序号和 CRC 比较 FPGA 输入、PS 输出和树莓派接收。
4. 注入树莓派断线、慢接收和重连，确认不拖慢 PL。

### 阶段 D：树莓派数字孪生

1. 先移植现有录制回放和实时网页。
2. 用人工位姿验证地图接口和关键帧。
3. 装车后接入真实 Odom/IMU，加入运动补偿和扫描匹配。
4. 输出车辆模型、轨迹、障碍物、风险区和平滑场景表面。

### 阶段 E：整机验收

1. 冷启动后无需电脑，FPGA与树莓派自动工作。
2. FPGA TFT 展示红青 AR 和基础车辆状态。
3. 浏览器展示树莓派数字孪生和参数面板。
4. 展示树莓派断开时FPGA仍能完成基础闭环。
5. 提交FPGA资源、时序、模块对拍、端到端延迟和掉线测试结果。

# 实机联调清单

本清单用于先在电脑端跑通 MID-360 + USB 摄像头，再做标定和 FPGA 移植。旧实验录制只用于格式参考；新验收必须录制真实赛题场景。代码与新录制文件都放在本项目目录，不写入 `可研`。

## 你需要准备

| 阶段 | 材料和信息 |
| --- | --- |
| 电脑首轮 | Windows 电脑、可用网口或 USB 网卡、USB 摄像头、相机数据线、网线、MID-360 原配转接线及符合该型号手册的电源、稳定的插座 |
| 安装与标定 | MID-360 和相机的牢固支架；能同时进入两者视野的棋盘格（当前默认 9×6 个内角点）、实测方格边长；卷尺、几件边缘清晰且处于不同距离和高度的静态目标 |
| 底盘 | 小车底盘及其供电、与电脑匹配的 USB 转 3.3V TTL 串口线、接线定义和当前固件/DFLink 版本；先架空车轮或断开驱动电机，仅看 Odom |
| 后续上板 | 7020 板准确型号及原理图/引脚手册、配套电源和下载线、OV5640 模组与排线、视频输出线和显示器；这些不影响电脑端首轮 |

开始前发我：MID-360 型号标签/线束照片、雷达 IP、电脑有线网卡 IP、点云目标端口、USB 相机编号和实际分辨率、底盘串口号/波特率及线序、板卡准确型号。电压和引脚以实物手册为准，不根据项目旧方案猜接线。相机编号和雷达地址要明确填入程序。

## 电脑端联调顺序

1. **只接雷达。** 用原配或核对过规格的线束给 MID-360 供电并接电脑有线网卡。按官方 Livox Viewer 2 / SDK2 的步骤，让雷达和电脑网卡在可通信网段，并把点云目标主机地址和端口设为本机。官方 SDK2 示例的主机点云端口是 `56301`，仍以实际配置为准。先在官方工具中确认有实时点云，再退出占用该端口的软件。
2. **只接 USB 摄像头。** 确认系统能预览，记录设备编号、实际宽高和稳定帧率。电脑阶段用 USB 摄像头；裸 OV5640 DVP 模组不直接作为 Windows USB 摄像头输入。
3. **跑双传感器原始链路。** 在本目录 PowerShell 中运行下面的实机命令。先保持设备静止，观察 `radar_packets`、`camera_frames` 持续增加，坏包/丢点计数和时间戳合理。确认俯视图的前后左右与现场一致；坐标轴不符时先核查安装和坐标约定。
4. **录制首批真实数据。** 固定支架后，录空场、一个近目标、一个远目标、两个分离目标、走动目标各一段；每段保留原始录制目录并写下目标距离、位置、光照、是否行驶。先录静止场景，再录低速行驶。行驶数据先用于检查断流与时延，不做未补偿的跨帧融合。
5. **标定。** 用棋盘格拍至少 8 张有效且角度/距离变化充分的图求 USB 相机内参；用多深度、多高度的雷达 3D 点与图像 2D 点求外参；在雷达点云中选至少 20 个地面点拟合地平面；用录制包估设备时差。外参点对至少 8 组，并检查重投影误差和画面实际对齐。固定 `CameraId` 和 `MountId`，只在参数匹配时打开目标框。
6. **融合验收。** 回放所有录制，核对近远距离、左右位置、目标数量、静止/移动、遮挡、雷达或相机断流后的撤框行为。记录误检、漏检、投影偏差、丢包、点数溢出和处理时延；根据现场数据调整配置文件。
7. **接底盘。** 先架空车轮或关闭电机，核对共地、TX/RX、电平和串口参数，再接 Odom。确认姿态和速度方向与实际动作一致。最后在低速行驶下复录数据。
